# UE-Side Adaptive Filtering for Intra-Cluster Localization

Simulation and measurement pipeline for the paper

> A. Piroddi, A. Kanakis, M. Opoku Agyeman, *"Adaptive Filtering at the User Equipment for
> Intra-Cluster Localization in User-Centric Networks"*, submitted, 2026.

Everything reported in the paper is produced by the notebooks in this repository: the
ray-traced datasets, the prediction and gating experiments, the measured-data processing, the
millimeter-wave localization results, and the three figures. The table in
[Claim provenance](#claim-provenance) maps every number in the paper to the notebook and cell
that computed it.

## What the work does

A terminal in a user-centric deployment is served by a *cluster* of distributed arrays. This
work moves the adaptive component from the network to the terminal and asks four questions:

1. does an online adaptive filter on the received CSI beat a fixed predictor computed offline?
2. when can the coefficient updates be switched off?
3. can the terminal localize itself *within* its serving cluster?
4. does the temporal evolution of the CSI itself carry position information?

The short answers: yes, because adaptive filtering buys robustness to non-stationarity rather
than asymptotic accuracy; whenever the environment is quasi-stationary, which a gate on the
innovation energy detects by itself; yes, to sub-meter accuracy where the cluster links are in
line of sight; and no — the innovation is a *when* signal, not a *where* signal.

## Data

### Simulated

Generated by the notebooks themselves with [Sionna](https://nvlabs.github.io/sionna/) 2.0.1,
using its built-in Munich scene. Nothing to download. Random seeds are fixed in every notebook,
so a rerun reproduces the datasets bit-for-bit on the same Sionna version.

### Measured

[dichasus-cf0x](https://dichasus.inue.uni-stuttgart.de/datasets/data/dichasus-cf0x/)
(DOI [10.18419/darus-2854](https://doi.org/10.18419/darus-2854)), distributed under CC-BY by
the University of Stuttgart. Download into `MyDrive/WH_RDCC/data_raw/`:

```
dichasus-cf02.tfrecords            4.55 GB
dichasus-cf03.tfrecords            5.54 GB
dichasus-cf04.tfrecords           10.31 GB
spec.json
reftx-offsets-dichasus-cf0{2,3,4}.json
```

Notebook 06 parses these at the **full 20.5 Hz sampling rate**. Do not reuse a
temporally subsampled export: subsampling is harmless for channel charting but destroys the
phase coherence that prediction depends on (see [Pitfalls](#pitfalls-worth-knowing-about)).

## Pitfalls worth knowing about

These cost us time and are easy to repeat. They are reported in the paper where they affect a
result, and listed here in full for anyone reusing the code.

**CSI sampling rate versus coherence time.** At 3.5 GHz a pedestrian covers more than half a
wavelength in 50 ms. CSI sampled that slowly is phase-decorrelated between consecutive samples,
the trivial predictor sits at NMSE ≈ 2, and *no* filter can improve on it. We re-trace geometry
every 50 ms but synthesize the CSI series at 5 ms from per-path Doppler shifts. The same applies
to measured data: do not subsample DICHASUS in time.

**Sionna disables edge diffraction by default.** `PathSolver.__call__` takes `diffraction=False`
and `edge_diffraction=False`. Edge diffraction fills shadows at 3.5 GHz far more than at 28 GHz,
so with the default settings the two bands produce near-identical cluster statistics — an
artifact that looks exactly like a negative result. Any multi-band clustering study must enable
it (notebook 09).

**TDoA reference consistency.** Measurement reports anchor delays to the energy-strongest array;
the geometric model naturally anchors to the earliest-arriving one. When the two differ — which
is routine in ray-traced data and never happens in a line-of-sight synthetic test — the mismatch
enters as a systematic bias of tens of meters. Use reference-invariant differences. Our synthetic
control deliberately misaligns the reference for this reason.

**Evaluation splits on CSI time series.** Adjacent samples at 5 ms lie centimeters apart. A
random train/test split lets every test sample find a neighbor from its own trajectory: in our
data that inflates localization accuracy 36-fold, for *every* feature set. Hold out whole
trajectories.

**Feature scaling before nearest-neighbor search.** Energies in dB are tens; delays in seconds
are microscopic. Without standardization the distance metric sees only the energies and every
feature set degenerates into received-power fingerprinting.

**Near-singular correlation matrices.** Oversampled CSI makes the Wiener normal equations
rank-deficient. Diagonal loading was not enough; a truncated pseudo-inverse with an aggressive
`rcond` is, and the truncation level that works best is itself evidence of low effective rank.

## Environment

```yaml
# environment.yml
name: ue-adaptive-localization
dependencies:
  - python=3.11
  - pip
  - pip:
      - sionna==2.0.1        # ray tracing; GPU strongly recommended
      - tensorflow           # TFRecord parsing for DICHASUS only
      - numpy
      - scipy
      - h5py
      - scikit-learn
      - pandas
      - matplotlib
```

On Colab the setup cell of each notebook installs what it needs. Notebooks 01, 02, 03, 08 and 09
need a GPU runtime; the rest run on CPU.

Note for Colab: installing Sionna upgrades NumPy, which leaves the running kernel with a mixed
NumPy state. The setup cells therefore restart the runtime once after installing and skip the
install on the second pass. This is expected behavior, not a crash.
